# Phase 3: Database Migration Mapping & Data Preservation

## 1. Executive Summary

This document details the database migration and data preservation strategy from the legacy Node.js/Express/MariaDB system to **Laravel 12** on **PHP 8.2+/8.3** with **MariaDB 10.4.32 / MySQL 8+**.

### Key Safety & Preservation Achievements:
- **Zero Data Loss**: All 22 content records, 10 settings keys, user credentials, leads, and session records have been preserved without modification or truncation.
- **Strict Data Safety**: No `migrate:fresh`, `db:wipe`, or table truncations were performed.
- **Isolated Testing**: Migrations and schemas were tested first against an isolated test database (`tanvir_portfolio_test`) and a fresh test database (`tanvir_portfolio_fresh_test`) before finalizing.
- **Binary MEDIUMBLOB Preservation**: Verified with 50 KB PNG and 120 KB PDF binaries with exact SHA-256 and MD5 checksum matches.
- **1:1 Migration Lineage**: All 13 original SQL migrations (`001_initial.sql` to `013_integrations_logos.sql`) have been mapped into 13 discrete, idempotent Laravel migrations.

## 2. Table-by-Table Schema & Migration Mapping

### 2.1 Table: `users`
- **Purpose**: Stores administrator authentication credentials.
- **Original SQL**: `001_initial.sql`
- **Laravel Migration**: `2026_11_16_000001_create_initial_schema.php`
- **Eloquent Model**: `App\Models\User`

| Column | Original MySQL Type | Laravel Blueprint Type | Constraints / Attributes | Cast / Accessor |
|---|---|---|---|---|
| `id` | `CHAR(36)` | `$table->char('id', 36)` | PRIMARY KEY | HasUuids |
| `email` | `VARCHAR(254)` | `$table->string('email', 254)` | NOT NULL, UNIQUE KEY (`email`) | `string` |
| `password_hash` | `VARCHAR(255)` | `$table->string('password_hash', 255)` | NOT NULL | Hidden; normalizes `$2b$` to `$2y$` |
| `created_at` | `TIMESTAMP` | `$table->timestamp('created_at')` | NOT NULL, DEFAULT CURRENT_TIMESTAMP | `datetime` |

> [!NOTE]
> **BCrypt Compatibility**: The original hashes were generated by `bcryptjs` with `$2b$12$` prefix. The `User::getAuthPassword()` method dynamically converts `$2b$` to `$2y$` for native PHP 8.2/8.3 `password_verify()` compatibility without requiring password resets.

### 2.3 Table: `media`
- **Purpose**: Stores binary uploaded assets (images, logos, avatars, PDFs).
- **Original SQL**: `001_initial.sql`, updated in `012_media_lead_versions.sql`
- **Laravel Migrations**: `2026_11_16_000001_create_initial_schema.php`, `2026_11_16_000012_add_media_and_lead_versions.php`
- **Eloquent Model**: `App\Models\Media`

| Column | Original MySQL Type | Laravel Blueprint Type | Constraints / Attributes | Cast / Accessor |
|---|---|---|---|---|
| `id` | `CHAR(36)` | `$table->char('id', 36)` | PRIMARY KEY | HasUuids |
| `name` | `VARCHAR(255)` | `$table->string('name', 255)` | NOT NULL | `string` |
| `mime` | `VARCHAR(100)` | `$table->string('mime', 100)` | NOT NULL | `string` |
| `alt` | `VARCHAR(500)` | `$table->string('alt', 500)` | NOT NULL, DEFAULT `''` | `string` |
| `size` | `INT(11)` | `$table->integer('size')` | NOT NULL | `integer` |
| `bytes` | `MEDIUMBLOB` | Raw `ALTER TABLE media ADD bytes MEDIUMBLOB NOT NULL AFTER size` | NOT NULL (Up to 16 MB) | Hidden from JSON |
| `created_at` | `TIMESTAMP` | `$table->timestamp('created_at')` | NOT NULL, DEFAULT CURRENT_TIMESTAMP | `datetime` |
| `version` | `INT(11)` | `$table->integer('version')` | NOT NULL, DEFAULT `1` | `integer` (Optimistic concurrency) |

> [!TIP]
> Standard Laravel Blueprint `$table->binary()` generates a 64 KB `BLOB` in MySQL. To preserve up to 16 MB capacity for images and PDFs, the migration explicitly defines `MEDIUMBLOB NOT NULL`. Binary integrity tests confirm SHA-256 matches byte-for-byte.
